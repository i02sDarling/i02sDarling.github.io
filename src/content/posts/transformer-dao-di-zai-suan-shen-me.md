## 一个巨大的函数

先把架构完整过一遍：这是后面所有东西的基础。文中关键计算都用 Excel 走过一遍，方便对照。

### Y = F(X)

![](/images/transformer-dao-di-zai-suan-shen-me/468b6a50e7.webp)

Google 的《Attention Is All You Need》被称为 **奠定了现在神经网络、或者说奠定了现在 AI** 的论文。

![](/images/transformer-dao-di-zai-suan-shen-me/0d78ac949b.webp)

**神经网络** 由多个节点组成：从 **输入层** 输入 X，经隐藏层输出 Y。神经网络就是一个大型的函数：Y = F(X)。

例如，把 B 站视频的 **播放、点赞、投币** 等数据作为 X，用模型判断视频是否值得推荐。

![](/images/transformer-dao-di-zai-suan-shen-me/2863afd494.webp)

图像任务可输入 3500 个像素值（每个为 0～255），逐层提取前额、眉毛、眼睛动作，再判断 **心理活动**。相比单层推荐示例，使用 **多层**，是为了**进一步提取深层次的特征**。

### 四大模块

Transformer 是一种神经网络架构，核心是 **注意力机制**。

![](/images/transformer-dao-di-zai-suan-shen-me/1967263c7e.webp)

Transformer 架构总共大的模块包含 **4 个模块**：

1. **输入层（Embedding）**：把「初识 Transformer」等输入转成向量。
2. **Attention（注意力层）**：分析输入词之间的相互关系。
3. **FFN（前馈神经网络）**：在矩阵 **线性相乘** 之外，通过激活函数引入 **非线性**，进一步加工特征。
4. **输出层**：根据处理后的表示给出结果，例如判断照片中的人是开心、愤怒还是惊慌。

实际模型会 **堆叠很多模块**。像「LLaMA 3、38B、48 个模块」这种配置数字随版本变，记住量级就行，别当常量。

### 三种架构

![](/images/transformer-dao-di-zai-suan-shen-me/9006acaeb0.webp)

三种常见架构为 **encoder only**、**encoder-decoder**、**decoder only**。

共同目标都是**提取特征**。

**encoder only**：将输入句子转成计算机可处理的特征表示。

**encoder-decoder**：同时包含编码器和解码器，以 **T5** 为例，主要用来说明 **机器翻译**。

**decoder only**：采用 **自回归** 方式生成文本；代表是 GPT、LLaMA、DeepSeek。

| 架构 | 代表 | 主要用途 |
| --- | --- | --- |
| Encoder only | BERT | 特征提取、语义理解 |
| Encoder-Decoder | T5 | 机器翻译 |
| Decoder only | GPT、LLaMA、DeepSeek | 自回归生成 |

### 下一个 token

GPT 的任务是：输入了一句话，去**预测下一个可能的单词**是什么。

用「我喜欢学习大模型」举例：假设下一个词是「学习」的概率 22%，其他候选 9%、5%，模型选一个接着往下写。**豆包**、**DeepSeek** 逐 token 吐字，走的也是这个过程。

有一种说法是 DeepSeek R1 的小说能力到了 **95% 的人类顶尖小说家的水平**——这是主观评价，不是测量结果。

![](/images/transformer-dao-di-zai-suan-shen-me/abbb7bd551.webp)

模型读取**上下文**，计算下一 token 在**词表**中的概率，再从候选中选一个输出。中文词表按 2 万、3 万个词估算，实际选择还涉及后面的采样策略。**Transformer 具体在做的事情，就是这一步。**

## 为什么必须深

### 信用分配

引入梯度，解决的是「几亿个旋钮怎么调」的问题。

训练网络 = 调参，但 GPT 级别的模型有**几千亿个权重**。怎么调？

+ 没有梯度：只能瞎试——把某个权重 +0.01，跑一遍看损失降没降。几千亿个参数，每个试一次都不可能
+ 有梯度：一次反向传播，**每个权重同时**拿到精确指令：“你调大一点损失会降 0.02，你调小一点会降 0.5”

所以梯度解决的问题叫**信用分配（credit assignment）**：损失这么高，几亿个参数里**各自该背多少责任、往哪边改**。没有它，深度学习根本训练不起来。

### 四十层

为什么要堆 40 层：因为语言理解是「多级抽象」，浅层表达不了。

拿一个例句走一遍，看每层大概在干嘛：

```plain
a fluffy blue creature roamed the verdant forest
```

+ **浅层（1~2 层）**：只看局部。"fluffy blue" 知道自己是形容词堆在一起；"the verdant" 知道后面大概率跟名词。都是“隔壁邻居”级别的信息
+ **中层**：开始组块。"fluffy blue" + "creature" 组成名词短语；"creature"（主语）和 "roamed"（谓语）建立主谓关系——注意此时要**跳过中间很多词**才能配对上
+ **深层**：高阶关系。"verdant forest" 是 roamed 的地点；"creature roamed the forest" 整个组成一个事件描述；甚至能推断 creature 大概是某种毛茸茸的动物

看明白了吗：**理解这句话需要“搭积木”式的多级组合**——字 → 短语 → 主谓 → 事件语义。浅层网络只有一两层积木，只能表达“谁和谁相邻”，表达不了“creature 生成的事件发生在 forest 里”这种嵌套结构。数学上可以证明：某些函数用浅网络表达需要指数级的宽度，用深网络只要线性层数。<span class="hl-red-bg">**深度 = 用合理的参数量表达复杂的组合逻辑**。</span>

### 连乘

为什么一定要「连乘」：因为层是嵌套的，求导数学上就长这样。

层是一层套一层的：`y = 第40层(第39层(...(第1层(x))))`。函数嵌套求导，链式法则规定就是乘起来，这不是设计选择，是微积分定律。

用一个具体小例子感受一下连乘怎么变成“消失”的。假设每层把输入的变化**放大 0.8 倍**：

```plain
x 变化 0.01
→ 第1层输出 h₁ 变化 0.01 × 0.8 = 0.008
→ 第2层输出 h₂ 变化 0.008 × 0.8 = 0.0064
→ ...
→ 第40层输出 y 变化 0.01 × 0.8⁴⁰ ≈ 0.0000013
```

现在从输出端看：损失对 x 的敏感度就是这串 0.8 的**连乘**——<span class="hl-red">**x 拼命变，y 几乎没反应**</span>。反过来训练时也一样：损失对浅层权重的梯度 = 一路乘回去的局部梯度 ≈ 0，浅层收不到学习信号。

这就是为什么必须“连乘”（链式法则躲不掉）、为什么连乘会消失（小于1的数越乘越小）、以及为什么残差连接是解药（每层变成 1 + 小数，乘不没了）。三个问题其实是一条因果链。

### 参数怎么学

例如输入「我喜欢自然语言处理」，模型预测的下一 token 与真实答案有差距，用 **损失函数** 度量，再更新参数。GPT 的训练数据量级在 **40T** token，也就是万亿到几十万亿，说明这个 Y=F(X) 是被海量样本一起训出来的。

顺带一组配置：LLaMA 的 40B、400B 系列有 **96 个头**，DeepSeek V3 有 **670 多 B**、约 **6700 亿** 参数。数字随版本变，关键是这些参数全靠 **梯度下降** 一点点调——反复用损失函数迭代里面每一个参数，让它越来越能预测准下一个 token。

### 一条少有人走的路

比如这句话："有两条路在我面前，我选择了那条少有人走的路。"那"roads"（路）这个 token 代表的是什么呢？

![](/images/transformer-dao-di-zai-suan-shen-me/71dabc92b2.webp)

它指代的就是 **roads**。一开始它是一个简单的向量（可能就是 1、2、3、4）；考虑了别的单词对它的影响之后，进行了一次偏移；再考虑其他单词之后，又对它进行了一次偏移。在语义里它就能指代：它是一条**马路**，并且是**少有人走的马路**。

![](/images/transformer-dao-di-zai-suan-shen-me/9ce9ef488e.webp)

## 从一句话到矩阵

**在模型内部，一个 token 就是一个向量**，而且<span class="hl-red-bg">位置编码是加在**最开始的输入向量**上的，不是加在 `Wq` 之后</span>。这一点很容易记反。

```plain
token "猫" → 查词表得到 ID (整数，比如 1234)
           → 查 embedding 表，取出第 1234 行
           → 得到向量 [0.2, -1.3, 0.5, ...]  ← 这就是这个 token 的向量
```

+ 模型不认识文字，一切都得变成数字，所以每个 token 都被表示成**一串数字**，这串数字就是**向量**。
+ **为什么要很多维**：一个数字装不下"猫"的含义。维度越多，能同时编码的特征越多（是动物？是名词？和谁相关？……）。所以用 512、768 这种大向量，而不是 1 个数。

<span class="hl-red">**一整句的词向量堆起来就是矩阵**</span>。完整链路如下。

**第 1 步：词 → token（分词）**

模型先把句子**切开**成 token，每个 token 再查词表换成**整数 ID**：

```plain
"我爱猫" → 分词 ["我", "爱", "猫"] → 查词表 → [102, 45, 1234]
```

+ 切法叫 **tokenization**。英文常用 subword（如 `playing` → `play` + `ing`），中文常按字或词切。
+ 词表就是所有 token 的清单，每个 token 有个固定编号（ID）。

**第 2 步：token → 向量（查表）**

模型里有一张 **embedding 表**，形状是 `(词表大小, d)`：

```plain
              第0维  第1维  ...  第d-1维
ID=0    →  [ ... ]
ID=1    →  [ ... ]
...
ID=102  →  [ 0.2, -1.3, 0.5, ... ]   ← "我" 的向量
ID=45   →  [ ... ]                    ← "爱" 的向量
ID=1234 →  [ ... ]                    ← "猫" 的向量
...
```

<span class="hl-red">**token 的 ID 就是行号**</span>，取出那一行 → 就是这个 token 的向量。查表得到的，不是算出来的。

**第 3 步：向量堆成矩阵**

一句有 n 个 token，就得到 n 个 d 维向量，**按顺序叠起来 → n×d 的矩阵**：

```plain
      第0维  第1维  ...  第d-1维
"我"  [ 0.2, -1.3,  ...   ...  ]   ← 第1行（pos=0）
"爱"  [ 0.5,  0.8,  ...   ...  ]   ← 第2行（pos=1）
"猫"  [ ...   ...   ...   ...  ]   ← 第3行（pos=2）
        ↑ 每一行 = 一个 token 的向量
```

+ **行** = token（序列方向，对应 `pos`）
+ **列** = 维度（对应 `i`）
+ 这就是 Transformer 的**输入矩阵**。

**总览**

```plain
"我爱猫"
   │ 分词
   ▼
["我","爱","猫"]  →  [102, 45, 1234]      (token → ID)
   │ 查 embedding 表（按行取）
   ▼
[ [..], [..], [..] ]                       (每个 ID → 一个 d 维向量)
   │ 堆叠
   ▼
n×d 矩阵  ──+ 位置编码矩阵──►  最终输入矩阵
   │
   ▼
×Wq / ×Wk / ×Wv  →  Q / K / V  ...
```

一句话：**词先切成 token 并编成 ID，再用 ID 去 embedding 表里按行取向量，n 个 token 的向量一叠就是一个 n×d 的矩阵，位置编码按行加到这个矩阵上。**

换个角度再说一遍：**token 就是一个 d 维向量；位置编码在「进模型最开始」就逐元素加到它上面，Q/K/V 是之后再算的，位置信息会顺着传进去。**

## Embedding 是学出来的

### 计算机怎么读一句话

先解决一个问题：**计算机是怎么识别「我喜欢学习大模型」这句话的**？

靠的是 **Embedding**，也就是**词向量**这种方式。下面从编号、one-hot 一路看到稠密表示。

### 降维矩阵

这个「降维矩阵」（降维操作）**就是 embedding 步骤，而且它是训练中学习出来的**。

那个"降维矩阵"（词表 15 × 5）就是**嵌入层（Embedding Layer）**的参数，叫嵌入矩阵 W_e。它跟模型的注意力、前馈网络一样，都是**可学习参数**。

训练开始时随机初始化，之后**每走一次反向传播都会更新它**：

```plain
损失 → 梯度 → 一路反传到嵌入矩阵 → 更新 W_e
```

**具体怎么学的**

嵌入矩阵的每一行对应一个词。训练时模型反复见到类似样本：

```plain
"小猫和小狗玩" → The dog and cat play
"小狗追小猫"   → The cat runs
```

梯度会不断微调 W_e：

+ `dog` 和 `cat` 的行 → 被推向"语义相近"的位置（因为它们在很多句子里扮演相似角色）
+ `play` 和 `runs` → 也被推近（都是动作）

于是训练完成后，语义相近的词在 5 维空间里天然靠在一起——**这正是 embedding 的意义：把"编号"变成"语义坐标"**。

**细节补充**

1. **"乘矩阵"其实是查表**：`词编号 → 取 W_e 对应那一行`。说"乘"是为了教学方便，实际就是 lookup。
2. **输出那边那个 5→15 矩阵 W_o 也是学出来的**，很多模型还做 **权重共享**：直接 `W_o = W_e 的转置`，节省参数、且让"进出的语义空间"一致。
3. 所以整条链：**嵌入矩阵（学）→ 模型主体（学）→ 输出矩阵（学）**，全都在同一个反向传播里被一起训练，不是手工设计好的。

一句话：**它既是 embedding 步骤，也是被训练出来的参数**——语言模型"懂语义"很大程度就体现在这张学出来的嵌入矩阵上。

### 稠密向量

在这种情况下，我们就引入**稠密向量**。

**稠密向量有个什么好处呢？**

![](/images/transformer-dao-di-zai-suan-shen-me/b88659b637.webp)

苹果与华为在「手机」语义上相近。用可解释的维度帮着理解：**它每一个维度可以去表征一个特点**。

+ 比如说第一维度，它表征的是水果——那华为没办法表征成水果，苹果是可以的；
+ 第二个维度，表征他们都具有物理的属性；
+ 第三个维度，表征他们在手机这个维度上它的比重是多少；
+ 最后一个维度表征的是气味。

这些维度只作直观类比：在现在的深度学习当中，每一个特征的维度它其实已经**不可解释**了。

**通过这样的方式有个什么好处呢？**

我们可以通过**向量与向量之间的距离**来定义两件事情之间的相互关系。

四维示例中，香蕉与猴子的距离为 **根号 7**，香蕉与原子能的距离为 **根号 100 多万**。通过这种表示，把名词、形容词、介词、代词等放入向量空间。

**所以我们要做的第一步是什么？**

第一步是将语言、图像等 **嵌入** 到计算机可处理的空间。那么这个计算机了解的语言就是 **embedding**，就是向量——而且是这种**稠密型**的向量。这里强调用多个数值共同表示特征。

### 维度该多少

**维度**选择与任务需要表达的关系有关。若只区分父亲、母亲、女人、小孩、国王、王后等十几个、二十个或几百个词，教学示例可用较少维度。

一个拟合的比方：两点可以用一条直线拟合，四点未必能用同一条直线。需要表达更复杂的关系，就得加参数、上**非线性**曲线。

在「性别、是否有孩子」之外，再加入 **权力** 关系以区分国王、王后，便可由二维扩到 **三维空间**。现在的模型基本上是 **4096 维**或者 **8192 维** 的 embedding 维度，具体看 config。

继续预训练或微调时，通常沿用已有架构的**维度**。很少有人真的从 0 到 1 搭一个架构再训一个模型，多数是在已有架构上继续训练、微调，做出适合自己场景的**领域模型**。

因此，先把输入变成 embedding，再通过后续结构建模关系。

## 位置编码

![](/images/transformer-dao-di-zai-suan-shen-me/d58326e768.webp)

> 图上 i 越往后越稀疏，这一点没有实际含义。看 p0 和 p1 就够了：它相当于指针，低维转得快、高维转得慢，拼起来构成一个唯一的指纹。 
>
> 用来表征两个东西 
>
> 1. **绝对位置**：看到这串数，就知道它是第几个 token（因为每个 pos 的组合唯一）。
> 2. **相对距离**：更妙的点——任意两个位置指纹的**点积**，算出来只跟它们的**距离 k** (两个token中间差多远)有关，跟具体在哪儿无关。
>

```plain
PE(pos)·PE(pos+k)  ≈  只取决于 k（距离）
```

「我打你」与「你打我」语义不同，位置编码用来区分 token 的位置与顺序。

> 这个原理不用现在钻透，后面讲 LLaMA 时会展开。
>

```python
PE(pos, 2i)   = sin( pos / 10000^(2i/d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d) )

# pos= 行 代表是第几个token 
# i = 列 代表 第pos个token的 第i维

所有token的第0维 都是sin 第1维都是cos
```

```plain
位置编码是什么

"猫"  ──查表──►  x = [0.2, -1.3, 0.5, ...]   (d维)
                        │
                   + PE(pos, ·) = [sin, cos, sin, ...]   (d维，逐元素加)
# 位置编码是sin,cos 这种 这里只是表示位置编码的形式 还需要加上原来的向量
                        │
                        ▼
              输入向量（含位置信息）
                        │
          ┌─────────────┼─────────────┐
         ×Wq           ×Wk           ×Wv
          ▼             ▼             ▼
          Q             K             V

如何运算的

猫的向量 x  = [ 0.2 , -1.3 ,  0.5 ,  0.8 ]
位置编码 PE = [ 0.84,  0.54,  0.01,  0.99 ]   ← 这串是 sin/cos 算出来的小数
相加(逐元素)= [ 1.04, -0.76,  0.51,  1.79 ]
              x[0]+PE[0]  x[1]+PE[1]  ...
```

公式中，**sin** 对应偶数索引，cos 对应奇数索引：

1. 第 2i 维使用正弦 sine。
2. 第 2i+1 维使用 **余弦（cosine）**。

例如按 5 维示意，第 0、2、4 维用 sin，第 1、3 维用 cos；实现时还需留意**维度**布局。

图中横轴 0、1、2、3、4 为 token 位置，纵轴 0、1、2、3 为特征维度。**position embedding（位置向量）** 与输入 embedding **等维**，逐元素相加；这里演示 **绝对位置编码**。

> 除了**绝对位置编码**，后面还有相对位置编码、旋转位置编码（RoPE），能更好地表示两个词之间的相对关系。
>

### 上下文长度

位置编码跟**上下文长度**是绑在一起的：想扩上下文，位置编码得先撑得住。

> 上下文长度这几年从 8K 涨到 128K、256K，现在常见 10 万，甚至有 100 万、200 万上下文的模型。这件事跟位置编码息息相关。
>

「我喜欢大语言模型」「我喜欢大」等文本转成 embedding，再加位置编码，**input 这部分就完成了**。
