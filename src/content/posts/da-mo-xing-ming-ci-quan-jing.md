## 一、表示层：文本怎么变成数字

### 1.1 one-hot：最原始、也最诚实的编码

**一句话：** one-hot 就是「给词表里每个词发一个座位号，轮到谁谁站 1，其余全 0」。

**例子：** 假设词表只有四个词 `[猫, 狗, 鱼, 鸟]`：

```
猫 = [1, 0, 0, 0]
狗 = [0, 1, 0, 0]
鱼 = [0, 0, 1, 0]
鸟 = [0, 0, 0, 1]
```

**它在大模型的哪一步：** 第一段「表示」的最开头。原始 Transformer 论文的输入就是 one-hot 乘一个权重矩阵，数学上等价于「查表」。

**三个硬伤，正好解释了 embedding 为什么必须存在：**

| 问题 | 具体表现 | 后果 |
| --- | --- | --- |
| 维度爆炸 | 词表 12.8 万，向量就是 12.8 万维 | 存不下、算不动，99.99% 是 0 |
| 完全正交 | 任意两个不同词的向量点积恒为 0 | 猫和狗、猫和鱼的距离一样远，学不出语义相似 |
| 无法泛化 | 每个词彼此独立 | 从「猫」学到的规律，一点也迁移不到「猫咪」 |

**替代是什么：** embedding 查表。关键在于——**embedding 层本质就是 one-hot 乘一个可学习矩阵**：

```
one-hot(长度 V) × W(V × d) = W 的第 i 行
```

所以它不是「另一种编码」，而是「把 one-hot 压缩成可学习、带距离的稠密向量」。这一步省了 V 倍存储，还让「猫」和「狗」可以只差 0.2 的距离。

**one-hot 死了吗？没有，它退到了监督信号的位置：**

- 交叉熵的 target 永远是 one-hot（或 label smoothing 的软化版）；
- 分类头 softmax 输出 12.8 万维概率，跟 one-hot 的「标准答案」比；
- 蒸馏时把 one-hot 换成教师的软分布，这就是白盒蒸馏。

**一句话总结：** <span class="hl-red-bg">one-hot 是「坐标」，embedding 是「坐标 + 距离」</span>。前者只表示身份，后者才携带语义。

### 1.2 token / tokenizer / BPE / 词表 / ID

- **token**：模型处理的最小单位。不是「字」，也不是「词」。英文常切 subword（`playing` → `play` + `ing`），中文按字或高频词。
- **tokenizer**：切 token 的工具。**它只负责切，不负责变向量**——这是最常混的一点。
- **BPE（Byte-Pair Encoding，字节对编码）**：最常用的切法。先把文本切成最小单元，再统计「哪两个相邻单元一起出现概率最高」，反复合并。所以「苹果树」三个字很可能被合成一个 token。
- **词表（vocab）**：所有 token 的集合。Llama 3 是 128256，Qwen 系约 15 万，某些纯中文教学模型只有 6400。
- **ID**：token 在词表里的整数下标，`猫` 可能对应 4823。**ID 本身没有语义**，它只是「embedding 表的行号」。

**一个常见误解：** 看到「15 → 5 → 15」别以为是降维损失。15 是词表大小（行数），5 是 d_model（语义维度）。**真正决定模型聪明程度的是 d_model，不是词表。**

### 1.3 embedding

形状 `(词表大小, d_model)` 的矩阵，按 ID 取行。Llama 3 8B 是 `(128256, 4096)`，一个 token 就是一个 4096 维向量。

**为什么是「查表」而不是「计算」：** 因为 ID 是离散整数，没有可做乘法的数值意义。整个网络里唯一把 ID 变成向量的动作，就是这一次按行索引。

### 1.4 logits / softmax / 采样三件套

- **logits**：模型最后一层输出的原始分数，未归一化。Llama 3 8B 输出 `1 × 128256`。
- **softmax**：把分数变成概率，`e^{z_i} / Σ e^{z_j}`，保证非负且和为 1。注意力机制里也用它把分数变成权重。
- **temperature（T）**：logits 先除以 T 再 softmax。T < 1 分布更尖锐（更确定），T > 1 更平坦（更随机），T = 0 等价贪心。
- **top-k**：只在概率最高的 k 个里采样。
- **top-p（nucleus sampling）**：按概率从高到低累加，凑够 p 就截断，剩下的全丢掉。
- **greedy / argmax**：直接取最大，输出完全确定。

**为什么大模型每次答得不一样：** 两个来源叠加。一是输入那个 `1 × d` 的向量本身是**随机初始化**的（训练好的是 Wq/Wk/Wv 这些权重，不是这个初值）；二是温度采样。<span class="hl-red">权重是确定的，随机性来自初值加采样。</span>

## 二、训练的基本词汇：loss、train error、过拟合

### 2.1 loss（损失）

**一句话：** loss 是「模型答得有多离谱」的一个数，训练就是把这个数往下压。

- 语言模型用**交叉熵**：正确 token 的概率越接近 1，loss 越接近 0。
- 数值直觉：`loss = -ln(p)`。p = 1 时 loss = 0；p = 0.5 时 0.69；p = 0.01 时 4.6。
- 一个漂亮的对照：词表 6400 的模型，随机乱猜时 loss ≈ `-ln(1/6400)` ≈ 8.76；实际训练常从 6.1 起步、收敛到 2 左右，说明它已经学到了相当强的分布。

### 2.2 train error / test error / 网络退化

**一句话：train error 是「在训练集上做错的百分比」，test error 是「在没见过的数据上做错的百分比」。**

三个词必须分清，混了就会得出完全错误的结论：

| 现象 | 名称 | 说明 |
| --- | --- | --- |
| train error 低、test error 高 | **过拟合（overfitting）** | 把训练集背下来了，没学到可迁移的规律 |
| train error 高、test error 也高 | **欠拟合（underfitting）** | 模型太弱、训练不够，或优化失败 |
| **层数变多，train error 反而更高** | **网络退化（degradation）** | 不是过拟合！是深了以后优化不动 |

第三种最反直觉。ResNet 论文的经典实验：20 层和 56 层对比，**56 层的训练误差反而更高**。如果 56 层只是「多叠了 36 个恒等映射」，它至少不该比 20 层差；既然更差，说明<span class="hl-red">深层网络连「学成恒等」都做不到</span>——梯度在往回传的路上衰减掉了。

这就是残差连接 `x + f(x)` 的动机：给梯度修一条直通浅层的高速路，把「最差也能学成恒等」变成结构上的保证。

**为什么现在很少听人说 train error：** 大模型预训练动辄几 T token，训练 loss 几乎永远在缓慢下降，参考价值低。大家看的是验证集 loss、下游 benchmark 和人工评估。但「train 高 test 低 = 过拟合；train 也高 = 欠拟合或优化失败」这个判断框架，面试一直在问。

### 2.3 epoch / step / batch / lr / warmup

- **batch**：一次喂进去几条样本。**batch size** 是条数；**等效 batch** = 每卡 batch × 卡数 × 梯度累积步数。
- **step**：一次参数更新。**epoch**：把整个数据集完整过一遍。
- **梯度累积（gradient accumulation）**：显存不够时，攒几个小 batch 的梯度再更新一次，模拟大 batch。
- **lr（学习率）**：每步走多远。太大一步跨过最低点来回震荡，太小走半天还在原地。
- **warmup**：前几百步把 lr 从很小线性升到目标值，防止一开始梯度太乱把模型带偏。**改用 Pre-Norm 之后，对 warmup 的依赖明显降低。**
- **cosine 退火**：lr 按余弦曲线从高缓慢降到接近 0。工程上常写成 `lr/10 + 0.5·lr·(1+cos(...))`，那个 `lr/10` 的偏移本身就是可调超参。

### 2.4 梯度消失 / 梯度爆炸

链式法则要连乘：

```
∂L/∂x₁ = ∂L/∂x₄₀ × ∂x₄₀/∂x₃₉ × … × ∂x₂/∂x₁
```

若每层因子是 0.8，40 层后变成 `0.8⁴⁰ ≈ 1.3 × 10⁻⁴`，浅层几乎收不到学习信号；若因子大于 1，就指数爆炸成 NaN。

**两个结构解药：** 残差（把每层从「乘以 0.8」变成「乘以 1 + 小数」）、归一化（把每层输出尺度锁死）。工程上再加**梯度裁剪**（`clip_grad_norm_`）兜底。

## 三、Transformer 的骨架

### 3.1 Block / 层 / 解码步

- **Block**：Transformer 的一个标准加工单元。内部顺序固定：自注意力 → Add & Norm →（交叉注意力 → Add & Norm）→ FFN → Add & Norm。
- **层 = 一个 Block**。堆 N 个就是深度：Llama 3 8B 是 32 层，70B 是 80 层，405B 是 126 层。
- **解码步**：生成一个 token 要走完全部 N 层，这叫一步。

**最容易埋坑的一题：**「40 层和 40 个解码步是不是一回事？」——**不是**。层是空间维度（一次前向里的纵向深度），解码步是时间维度（自回归的横向次数）。

### 3.2 QKV / self-attention / multi-head / causal mask

- **Q（Query，查询）**：我在找什么。
- **K（Key，键）**：我能被谁匹配。
- **V（Value，值）**：我实际携带的内容。
- **公式**：`Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V`。QK 决定「看谁」，softmax 定权重，V 决定「拿走什么」。
- **为什么要乘 Wq / Wk**：不是为了算相似度，而是把词投影到「我找什么 / 我能被谁匹配」两种角色视角。否则 Q·K 退化成词义相似度，学不到「形容词关注名词」这类句法关系。
- **为什么要除 √d_k**：两个均值 0、方差 1 的向量点积后，方差会变成 d_k；除完把方差拉回 1，softmax 才不会饱和成近似 one-hot 的尖峰。
- **multi-head（多头）**：把 4096 维拆成 32 头 × 128 维，各头独立算完再拼接。**目的不是「多算几遍更准」，而是给多组随机初始化，总有一组学得好。**
- **causal mask（因果掩码）**：把右上角（未来位置）的分数置成 −∞，softmax 后权重为 0。不加就是偷看答案，训练全废。

### 3.3 Encoder-Decoder / Encoder-only / Decoder-only

先给结论：**这三种是同一个 Transformer 的三种「注意力可见范围」配置，区别只在 mask 和有没有交叉注意力。**

| 架构 | mask | 注意力形状 | 代表 | 擅长 | 现在地位 |
| --- | --- | --- | --- | --- | --- |
| **Encoder-Decoder** | Encoder 双向，Decoder 因果 | Encoder 内 N×N；Decoder 内 L×L；交叉注意力 **L×N** | 原始 Transformer、T5、BART、Whisper | 输入输出长度解耦：翻译、语音识别、摘要 | 特定领域仍在用，通用大模型里已边缘化 |
| **Encoder-only** | 无 mask，全双向 | N×N 满编 | BERT、RoBERTa、BGE、各类 embedding 模型 | 理解类：分类、NER、句向量、RAG 召回 | **RAG 里活得很好**，但不是生成模型 |
| **Decoder-only** | 因果 mask | L×L 下三角 | GPT 系、Llama、Qwen、DeepSeek、Mistral | 生成、对话、推理、工具调用 | **绝对主流** |

**Encoder 和 Decoder 各自在干什么：**

- **Encoder**：一次读完整句，每个位置都能看见所有位置（双向），输出「带上下文的表示」。**编码一次就冻结。**
- **Decoder**：只能看左边，逐词生成。**解码 N 次。**
- **交叉注意力（cross-attention）**：Decoder 用自己当前的 Q，去查 Encoder 那份编码结果的 K/V。形状是「解码长度 × 编码长度」，不是正方形。**Q 来自解码侧，K/V 由编码结果经 cross 自己的 Wk/Wv 投影——Encoder 内部的 Q/K/V 不外传。**

**训练用 teacher forcing：** 整句错位并行喂（输入 `[BOS] 我 喜欢`，标签 `我 喜欢 篮球`），一次算完所有位置的 loss；推理时才逐词自回归。

**为什么 decoder-only 赢了（高频面试题）：**

1. **训练目标统一**：任何文本都能当「下一个词预测」的监督，不需要构造「输入-输出对」，数据利用率最高。
2. **一个模型干所有事**：翻译、摘要、问答、写代码都能塞进「prompt → completion」，不用为每个任务改结构。
3. **KV Cache 能复用**：生成时前缀的 K/V 算一次存起来，后面只算新 token。
4. **scaling 更干净**：同样参数量和算力，decoder-only 的 scaling 曲线最平滑、最好预测。
5. **涌现能力**：in-context learning、few-shot、思维链，在 decoder-only 上表现最明显。

**Encoder-Decoder 没落了吗？没有。** 翻译、语音（Whisper）、TTS、图像描述这类「输入长、输出短且结构固定」的任务，Encoder 一次编码 + Decoder 多次解码仍然更省、更准。<span class="hl-red">选架构看任务，不看潮流。</span>

### 3.4 FFN（前馈网络）

```
FFN(x) = W₂ · act(W₁ · x + b₁) + b₂
```

典型是 `512 → 2048 → 激活 → 512`，中间维度通常是 d_model 的 4 倍（Llama 3 8B 是 4096 → 14336）。

**分工一句话：attention 负责「词与词交流」（跨 token），FFN 负责「每个词自己加工」（逐 token 独立、参数共享）。**

**为什么必须有 FFN：** 注意力本质是加权求和，是**线性**的。没有 FFN 里的激活函数，叠一百层还是线性变换，等于一层。**FFN 是全模型唯一的非线性来源**，也是参数量的主要去处（约占 2/3）。

### 3.5 残差连接

```
y = x + Sublayer(x)
```

**直接相加，没有「自动判断这一层好坏再决定加不加」的开关。**

三个作用：① 层只学「增量」，不必重造整个表示；② 给梯度一条直通浅层的高速路，解决退化；③ 让「多叠几层至少不变差」成为结构上的保证。

**注意维度必须一致**：这就是为什么每个 Block 的输入输出都锁死在同一组维度（如 `8 × 512`），否则加不起来。

### 3.6 BOS / EOS

- **BOS（Begin of Sequence）**：序列开头标记。Llama 3 的 BOS id 是 128000。
- **EOS（End of Sequence）**：结束标记。**SFT 数据结尾必须加 EOS，否则模型学会了「一直说下去」。**

## 四、激活函数：ReLU 与它的替代者

### 4.1 ReLU 是什么

```
ReLU(x) = max(0, x)
```

正数原样通过，负数直接归零。

**例子：** 输入 `[-3, -0.5, 0, 2, 7]`，输出 `[0, 0, 0, 2, 7]`。

### 4.2 当年为什么必须换掉 sigmoid / tanh

sigmoid 在 |x| 较大时导数趋近 0（饱和），梯度连乘几十层直接消失；tanh 好一点但同样饱和。ReLU 在正区间**导数恒等于 1**，怎么乘都不衰减——这是它能训练深层网络的根因（AlexNet / VGG / ResNet 时代）。

### 4.3 ReLU 的四个优点

| 优点 | 具体 | 为什么重要 |
| --- | --- | --- |
| 计算极便宜 | 一次比较，没有 exp、没有除法 | 大模型里 FFN 占大头，省一点就是全局省 |
| 不饱和 | 正区间梯度恒为 1 | 缓解梯度消失，能堆深 |
| 稀疏激活 | 约一半神经元输出 0 | 特征解耦、省算力、有正则效果 |
| 收敛快 | 相比 sigmoid 快数倍 | 当年训练时间直接砍半 |

### 4.4 ReLU 的四个缺点

| 缺点 | 具体 | 后果 |
| --- | --- | --- |
| **Dying ReLU（神经元死亡）** | 负区间梯度恒为 0，一旦某神经元对所有输入都为负，参数永远不更新 | 学习率大、初始化差时整片神经元「死掉」，容量白扔 |
| 零点不可导 | x = 0 处左右导数分别是 0 和 1 | 工程上取次梯度 0 即可，实际影响很小，是理论洁癖问题 |
| 输出非零中心 | 均值偏移为正 | 下一层输入有偏，收敛变慢，要靠归一化补救 |
| 无上界 | 输出可以无限大 | 需要配归一化和较小学习率，否则数值不稳 |

### 4.5 家族演进：一条「把负区间救回来 + 把拐角磨圆」的线

| 函数 | 公式 | 改了什么 | 现在谁用 |
| --- | --- | --- | --- |
| ReLU | `max(0, x)` | 基线 | CNN、移动端（ReLU6） |
| LeakyReLU | `max(0.01x, x)` | 负区间给个小斜率，防死亡 | 少量 CV、GAN |
| PReLU | `max(ax, x)`，a 可学习 | 斜率让模型自己学 | 人脸识别等 |
| ELU | `x > 0 ? x : α(eˣ − 1)` | 负区间饱和到 −α，输出更接近零中心 | 少用 |
| **GELU** | `x · Φ(x)`（Φ 是正态 CDF） | **把拐角磨成平滑曲线** | BERT、GPT-2、ViT |
| **SiLU / Swish** | `x · sigmoid(x)` | 平滑、非单调（负区间有个小下凹） | **SwiGLU 内部用的就是它** |

### 4.6 SwiGLU：现在 LLM 的真正主流

```
SwiGLU(x) = SiLU(xW₁) ⊙ (xW₃)，再乘 W₂ 降维
```

`⊙` 是逐元素相乘。

**它比 ReLU / GELU 多了一个「门」：** 一路算 `SiLU(xW₁)` 当「内容」，另一路 `xW₃` 当「闸门」，两者相乘决定放多少过去。**这等价于让网络自己学「这个特征该不该激活、激活多少」，而不是像 ReLU 那样写死一个阈值 0。**

**为什么它赢了（老实说）：** 不是理论推导出来的，是 Google 在 GLU Variants 那篇论文里把各种变体刷了一遍，SwiGLU 在大量数据集上分数最高。**这基本是「炼丹炼出来的」。**

**代价：** 三个矩阵（W₁、W₃、W₂）而不是两个，参数量多 50%。所以工程上把 FFN 中间维度从 `4d` 降到约 `8/3 d`（Llama 14336 ≈ 4096 × 3.5），保持总参数不变。

### 4.7 现在到底用什么（分场景，别一刀切）

| 场景 | 主流选择 | 原因 |
| --- | --- | --- |
| LLM 的 FFN | **SwiGLU**（Llama / Qwen / DeepSeek / Mistral / PaLM / Gemma 全是） | 分数最高，门控表达力强 |
| BERT 类 / ViT | GELU | 平滑、当时最优，生态惯性 |
| CNN / 移动端 | ReLU、ReLU6 | 极便宜，量化友好，够用 |
| Diffusion / 小模型 | SiLU、GELU | 平滑利于生成质量 |

**所以「ReLU 有没有上位替代」的答案是分层的：**

- 在**大语言模型的 FFN 里**，它已经被 SwiGLU 取代，GELU 是中间站；
- 在**卷积网络和端侧**，它还是默认选项，因为「够用 + 最便宜」。

<span class="hl-red-bg">替代不是「更高级」，是「场景变了」。</span>

## 五、归一化：LayerNorm 到 RMSNorm

### 5.1 归一化到底在干什么

**不是「把均值变成 0」这么简单。真正目的是把每一层输出的「尺度和幅度」锁死**，让深层网络不会因为数值越来越大或越来越小而失稳。

### 5.2 LayerNorm

```
y = (x − μ) / √(σ² + ε) × γ + β
```

对**单个 token 的所有维度**做：求均值 μ → 逐元素减 μ → 求方差 σ² → 除标准差 → 乘 γ 加 β。

**开销：** 两次 reduce（求和、求平方和）+ 一次逐元素减 + 一次逐元素除。每个 token、每一层都要做一遍。

### 5.3 RMSNorm

```
y = x / √(mean(x²) + ε) × γ
```

**只做两件事：** 算均方根 RMS（一次 reduce），然后除。**砍掉了「减均值」和偏置 β。**

**为什么砍了还不崩？** 数学上：

```
RMS² = σ² + μ²
```

只要 μ ≠ 0，RMS 一定大于 σ——<span class="hl-red">除以一个更大的数，照样能把幅度压住</span>。均值偏移交给后面的残差和线性层去吸收。

**例子：** `x = [1, 2, 3]`

| 方法 | 计算 | 结果 | 性质 |
| --- | --- | --- | --- |
| LayerNorm | μ = 2，σ ≈ 0.8165 | `[-1.22, 0, 1.22]` | 均值 0、标准差 1 |
| RMSNorm | RMS = √(14/3) ≈ 2.160 | `[0.463, 0.926, 1.389]` | 均方根 1、均值 0.926 |

结果不一样，但**「尺度被锁死」这个目的达到了**，而且省了两步操作。

**省多少：** 原论文测出 7%~64% 的归一化加速（取决于实现），端到端通常几个百分点；32 层堆起来很可观。

**现状：** Llama 全系、Qwen、DeepSeek、Mistral、Gemma **全部用 RMSNorm**。LayerNorm 仍活在 ViT、Diffusion（DiT 的 AdaLN）、多模态 projector 里——那些场景对「去均值」更敏感，层数也没那么多，省这点不值得。

### 5.4 Pre-Norm vs Post-Norm

| | 位置 | 公式 | 特点 |
| --- | --- | --- | --- |
| **Post-Norm** | 子层之后 | `LN(x + Sublayer(x))` | 原版 2017 论文；深了不稳，**依赖 warmup** |
| **Pre-Norm** | 子层之前 | `x + Sublayer(LN(x))` | 现在主流；**更稳、收敛更快、不依赖 warmup，能扩到上百层** |

**为什么 Pre-Norm 赢：** 残差那条直通路径上**没有任何归一化**，梯度可以干干净净地传回浅层；Post-Norm 把 LN 放在残差之后，等于在高速路上设了个收费站，深了就容易堵。代价是表达力略弱，所以有的模型在最后加一个额外 LN 收尾。

### 5.5 QK-Norm：2024 年之后的新增补

**做法：** 对注意力里的 Q 和 K 各自再做一次 RMSNorm（只作用在 head 维度上），然后再算 `QKᵀ`。

**解决什么：** 大模型训练到中后期，注意力 logits 会突然变得极大，导致 softmax 饱和、loss 尖峰甚至崩掉。QK-Norm 直接把 Q、K 的幅度锁死，从源头掐掉这个尖峰。

**谁在用：** Qwen3 全系、部分视觉模型（ViT-22B 最早用）。**这是「归一化」从「每个 Block 入口」扩展到「注意力内部」的一次细化**，成本几乎为零。

## 六、位置编码：RoPE 到底有没有被替代

### 6.1 为什么需要

注意力是「加权求和」，天生**对顺序不敏感**：把 token 顺序打乱，`softmax(QKᵀ)V` 的结果只是跟着换行，语义完全一样。所以必须额外注入位置信息。

### 6.2 四代方案

| 代 | 方案 | 做法 | 现状 |
| --- | --- | --- | --- |
| 1 | 正弦绝对编码 | `PE(pos, 2i) = sin(pos / 10000^{2i/d})`，奇数维用 cos，直接加到 embedding 上 | 原版 Transformer，已淘汰 |
| 2 | 可学习绝对编码 | 每个位置一个可训练向量 | BERT / GPT-2，已淘汰（不能外推） |
| 3 | **RoPE** | 按位置**旋转** Q、K | **LLM 绝对主流** |
| 4 | ALiBi | 给注意力分数加一个与距离成正比的负偏置 | BLOOM 用过，现在少 |

### 6.3 RoPE 怎么工作

不改向量内容，只按位置旋转：第 1 个不转，第 2 个转 θ，第 m 个转 mθ。4096 维拆成 2048 组二维平面，每组用复数 `e^{imθ}` 乘一下即可。

**三个好处：**

1. 两个 token 的注意力分数只取决于**相对距离**（旋转后点积里自然出现位置差）；
2. 长序列不失效；
3. 位置和内容融在一个向量里，不额外占维度。

**关键细节：旋转只作用在 Q、K 上，V 不转。** 因为位置只在 `QKᵀ` 这个分数里起作用，V 只是被加权搬运的内容。

### 6.4 现状：RoPE 没有被替代，被替代的是「旧的绝对编码」

这里必须纠正一个流行说法。<span class="hl-red-bg">「现在不用 RoPE 了，都用 XXX」是错的。</span> Llama 3、Qwen 2.5/3、DeepSeek V2/V3/R1、Mistral、Gemma——**全部用 RoPE**。真实发生的变化是三件事：

1. **长上下文不换编码，改 RoPE 的参数**：Llama 3 把 `rope_theta` 从 10000 调到 500000，每步旋转角变小，上下文从 8K 扩到 128K（分六个阶段爬上去）。
2. **外推靠插值**：Position Interpolation（把位置线性压缩回训练范围）、NTK-aware 缩放、YaRN、LongRoPE——**都是 RoPE 的变体，不是替代品**。
3. **DeepSeek 的 decoupled RoPE**：MLA 要把 KV 压到低秩隐空间，但 RoPE 是「逐维旋转」，和低秩压缩不兼容，所以额外留一小段**不压缩的维度专门放 RoPE**。这叫「解耦」，**不是放弃 RoPE**。

**ALiBi 为什么没赢：** 外推确实好，但它只是给分数加线性惩罚，表达力比「旋转」弱，且和 FlashAttention 的高效实现配合不如 RoPE 顺。**NoPE（完全不加位置）** 只在少数研究和部分层里出现，不是主流。

**一句话：位置编码这条线上，被淘汰的是「绝对位置 + 直接相加」，赢家是「相对位置 + 旋转」，而且赢得很彻底。**

### 6.5 M-RoPE：多模态带来的三维版本

视频/图像不只有「第几个 token」，还有「第几帧、第几行、第几列」。**M-RoPE（Multimodal RoPE）** 把位置拆成时间、高度、宽度三个分量，各自做旋转，再拼起来。Qwen2.5-VL、Qwen3-VL 都用这套。**本质仍是 RoPE，只是从一维扩展到三维。**

## 七、效率结构：GQA、MLA、MoE、KV Cache

这四个词共同点：**不改模型能力，只改「同样的算力能换多少效果」。**

### 7.1 MHA / MQA / GQA

| 名称 | Q 头数 | K/V 头数 | KV Cache 大小 | 代表 |
| --- | --- | --- | --- | --- |
| MHA（多头） | 32 | 32 | 1× | 原始 Transformer、GPT-3 |
| MQA（多查询） | 32 | 1 | 1/32 | 早期推理优化 |
| **GQA（分组查询）** | 32 | 8（4 个 Q 共享一组 KV） | 约 1/4 | Llama 2 70B、Llama 3 全系、Qwen、Mistral |

**为什么 Q 不能分组、KV 必须少：** Q 相同且 K、V 也相同，算出来的结果就完全重复，多头失去意义；反过来 KV 多会让 KV Cache 吃显存，序列越长越撑不住。<span class="hl-red">GQA 就是在「多头表达力」和「KV 显存」之间取的工程最优解。</span>

### 7.2 KV Cache

自回归生成时，前面 token 的 K、V 已经算过且不再变，存起来，新 token 只算自己的 Q 去查它们。**每步注意力从 O(N²) 降到 O(N)。**

**显存公式：**

```
KV Cache 显存 = 2 × 精度字节 × 层数 × hidden × max_seq × batch
```

那个 2 是 K 和 V 各一份。**这就是 `max_sequence` 设大就 OOM 的原因**：显存按最长序列预留。3090 上 7B 用 FP16 已占 14GB，只剩约 20K 上下文。

### 7.3 MoE / Router / Shared Expert

- **MoE（混合专家）**：把一个大 FFN 拆成若干专家，每个 token 只走其中几个。**只改 FFN 层，注意力不动。**
- **Router（门控）**：对每个 token 算路由分，softmax 后取 top-K（1~8 个），归一化，只加权求和被选中的专家。
- **Shared Expert（共享专家）**：留一个专家**每个 token 必走**（存通用知识），再从其余专家里选 top-K（存专门知识）。DeepSeek 系的做法。
- **好处：** 总参数几百 B，但每次前向只激活一小部分，推理成本按激活参数算。DeepSeek-V3 是 671B 总参、37B 激活。
- **代价：** 显存要装下全部专家；路由不稳会导致专家负载不均；训练更难。

**2024 年之后的一个重要改进：aux-loss-free 负载均衡。** 传统 MoE 要加一个「辅助损失」逼各专家负载均衡，但它会干扰主任务。DeepSeek-V3 改成给每个专家维护一个偏置项，按负载动态加减，**不引入额外梯度**，效果更好也更稳。

**稠密 vs MoE 一句话：** 稠密模型每次前向所有参数都参与，小规模就能出效果；MoE 要几百 B 才玩得动，个人根本部署不起。

### 7.4 MLA（Multi-head Latent Attention）

DeepSeek-V2 提出。把 QKV 先压到一个低维隐空间（如 512 → 128）再算，**KV Cache 能压到原来的几分之一**，效果不降反升。代价是实现复杂，且要处理 RoPE 与低秩压缩的冲突（就是上面说的 decoupled RoPE）。

### 7.5 稀疏注意力与线性注意力：长上下文的两条新路

上下文从 128K 往 1M 走，标准注意力的 O(N²) 撑不住了，于是出现两条路线：

| 路线 | 做法 | 代表 | 特点 |
| --- | --- | --- | --- |
| **稀疏注意力** | 只算一部分 token 对（选 top-k 或按块选） | DeepSeek **DSA**（V3.2-Exp）、Native Sparse Attention | 仍是注意力，精度损失小，**长文本成本大降** |
| **线性注意力** | 把 softmax 注意力换成可递推的线性形式，复杂度 O(N) | **Gated DeltaNet**、Mamba-2、lightning attention | 快、省显存，但纯线性表达力弱 |
| **混合架构** | 大部分层线性 + 少数层全注意力 | Qwen3-Next、MiniMax-01、Jamba | **当前最务实的折中**：既快又不掉太多 |

**结论：2025 年之后，「全注意力 + GQA」不再是唯一答案，混合架构开始进主流模型。** 但要注意：很多号称「线性注意力」的模型，仍保留少量全注意力层来兜住召回类任务。

### 7.6 MTP（Multi-Token Prediction）

训练时让模型**一次预测未来多个 token**（DeepSeek-V3 预测额外 1 个），而不是只预测下一个。

**两个收益：** ① 训练信号更密，数据效率更高；② 推理时可以拿这几个头做**投机解码**（先草拟几个 token，再让主模型一次验证），提速明显。

## 八、后训练：从 SFT 到 DPO 再到 RLVR

这一段回答「模型已经会说话，怎么教它好好答」。

### 8.1 三段流水线

| 阶段 | 干什么 | 数据 | 类比 |
| --- | --- | --- | --- |
| **预训练（pretrain）** | 学「文字与文字的关系」 | 几 T token 的无标注语料 | 出生到高中 |
| **SFT（监督微调）** | 学「收到指令该怎么答」 | 几万~几十万条 QA 对 | 进入社会工作 |
| **RLHF** | 定 KPI，学「什么叫答得好」 | 偏好对比数据 | 定 OKR 自己探索 |

**SFT 的天花板：它只教「该怎么答」，教不了「不该怎么答」。** 要让模型学会拒绝，必须上强化学习。

### 8.2 chat template / loss mask / NEFTune

- **chat template**：把多轮对话拼成模型认识的格式，用特殊 token 隔开 system / user / assistant。**SFT 与预训练的第一大差异。**
- **loss mask**：只在 assistant 的回答部分算 loss，用户输入部分置 0。**第二大差异**——不然模型会去学「怎么提问」。
- **NEFTune**：给 embedding 加 `alpha/√dims` 的均匀噪声，防过拟合。alpha 一般 0~10、多数设 5；在 Llama2 7B 上单这一项准确度能涨 10% 以上。**第三大差异。**

### 8.3 LoRA / rank / alpha / QLoRA / NF4

- **LoRA**：冻结原权重 W，只训一个低秩增量 `ΔW = A × B`。4096×4096 的 1677 万参数，拆成 4096×16 和 16×4096 只剩 13 万，省 90% 以上。
- **rank（r）**：那个 16 就是秩。**越小参数越少、精度损失越高**，常取 4/8/16。
- **alpha**：缩放系数，控制 `ΔW` 加回去的强度，常设 `alpha = 2r`。
- **省的是显存不是算力**：反向传播仍要算，但可训练参数、优化器状态、梯度全都大幅缩小。
- **QLoRA**：把**冻结的基座**量化到 4bit（NF4），LoRA 部分仍用 BF16 训。32B 模型才塞得进单卡。
- **NF4**：4bit NormalFloat，利用「LayerNorm 后权重近似正态分布」做分位量化，16 个格子密集分给中间、稀疏分给长尾。再叠加**双重量化**（把 scale 再压一次），额外开销从 0.5 bit/参数降到 0.127 bit/参数。

**一条要记住的判断：能做全量就别 LoRA。** 原论文说精度只降 2~3%，实际 PEFT 效果没那么好。LoRA 适合「问答记忆」和「风格调整」；涉及领域知识、能力、function call，该全量。

### 8.4 RM / PPO / GRPO / DPO / KL

| 名词 | 是什么 | 关键点 |
| --- | --- | --- |
| **RM（Reward Model）** | 给回答打分的模型 | **只换一个头**：`hidden × vocab` → `hidden × 1`；**只排序不打绝对分**，loss = `−log σ(chosen − rejected)` |
| **PPO** | 在线策略梯度算法 | **四个模型**：actor 生成、reward 打分、reference 冻结算 KL、critic 估 V(s)；把序列级奖励摊到每个 token |
| **GRPO** | PPO 的省显存版 | **砍掉 value model**，用「同一组内多个回答的平均分」当基线；DeepSeek-R1 用的就是它 |
| **DPO** | 直接偏好优化 | **不用 RM、不用生成**，三行 loss 直接吃 chosen/rejected；off-policy |
| **KL 散度** | 两个分布差多远 | `Σ P·log(P/Q)`，相同为 0；用来把新模型拴在原模型附近，防跑偏 |
| **on-policy / off-policy** | 数据是不是当前模型自己产的 | PPO/GRPO 是 on-policy（边打边学）；DPO 是 off-policy（看录像学） |
| **PRM / ORM** | 过程奖励 / 结果奖励 | PRM 看每一步，ORM 只看最终答案；**ORM 上限更高，PRM 更稳** |

**一句话选型：** 有标准答案（数学、代码）→ GRPO + 规则奖励；开放任务（写作、对话）→ 训 RM + PPO；只有偏好对、想省事 → DPO。

### 8.5 RLVR：2025 年之后最热的一条线

**RLVR = Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习。**

一句话：**只挑那些「对错可以自动判」的任务做强化学习**——数学答案能对，代码能过单元测试，格式能正则匹配。判不了的就先不训。

**为什么它成了主流：**

1. **不需要 reward model**，省掉最难训的一环，也就不存在 reward hacking 的温床；
2. **信号干净**，对就是对、错就是错；
3. **能逼出长思维链**：模型发现「多想几步更容易对」，思考长度会自己长出来，出现「等一下，我换个思路」这种自我纠错。

**代价与边界：** 它只能训「有标准答案」的领域。写作、共情、审美这类没有唯一答案的任务，仍然要回到人类偏好（RLHF / RM）。<span class="hl-red">这也是为什么推理模型在数学代码上突飞猛进，在文风上反而容易变得啰嗦。</span>

### 8.6 GRPO 与 DPO 的变体

2024 年之后，这两个算法各自长出了一批改良版，名字很花，但动机都很朴素：

| 变体 | 改了什么 | 解决什么 |
| --- | --- | --- |
| **DAPO** | 解耦裁剪范围、动态采样、token 级 loss | GRPO 训练不稳、长回答梯度被稀释 |
| **Dr. GRPO** | 去掉长度归一化和标准差归一化 | 避免模型学会「写长一点分数更高」 |
| **GSPO** | 把重要性比值从 token 级改成序列级 | 长序列方差太大 |
| **SimPO** | 去掉 reference model，用长度归一化的平均 logprob | 省一半显存 |
| **ORPO** | 把 SFT 和偏好对齐合成一步 | 省一个阶段 |
| **KTO** | 只要「好/坏」二元标签，不需要成对 | 数据难凑成对时可用 |

**记忆方式：GRPO 系在改「怎么算优势、怎么裁剪」，DPO 系在改「怎么省掉 reference、怎么少标数据」。**

### 8.7 灾难性遗忘 / 拒绝采样

- **灾难性遗忘**：只在新数据上训，旧能力被覆盖。解药是掺预训练数据、LoRA 冻结主干、小学习率。
- **拒绝采样（rejection sampling）**：让模型自己生成一批，挑好的留、坏的当 rejected。**DPO 的 5000 组 ≈ 纯 SFT 的 2~4 万组**，因为压的正是模型自己的 bad case。

## 九、应用层：提示词、RAG、Agent

### 9.1 提示词参数

| 参数 | 作用 | 经验值 |
| --- | --- | --- |
| temperature | 随机性 | 事实问答 0~0.3，创作 0.7~1.0 |
| top_p | 累积概率截断 | 0.9~0.95 |
| top_k | 只在前 k 个采样 | 10~50 |
| max_tokens | 输出上限 | 按场景 |
| repetition_penalty | 抑制重复 | 1.0~1.2 |
| seed | 复现 | 评测时固定 |

- **few-shot**：给几个正反例。**用错反而伤泛化**，不是越多越好。
- **CoT（思维链）**：让它先写推理再给答案。**推理模型（o1/R1 类）不支持 few-shot 和 JSON schema**，只给「任务 + 原始数据」。

### 9.2 function call / structured output / MCP

- **function call**：把工具的函数名、参数、**description** 交给模型，由模型自己判断「要不要调、调哪个」。**判决标准就是 description 写得好不好。**
- **structured output**：`response_format` 强制 JSON。严格模式用 JSON Schema；开源侧靠**约束解码**（XGrammar、Outlines、llguidance）在采样时就把非法 token 概率置零，比「生成完再解析」可靠得多。
- **MCP（Model Context Protocol）**：2024 年 11 月提出，2025 年被主流厂商广泛采纳，成为**工具接入的事实标准**。本质是「给工具外面加一层统一封装」，让不同模型、不同客户端用同一套方式接工具。**它是标准化，不是新能力。**

### 9.3 RAG 名词

| 名词 | 含义 | 关键点 |
| --- | --- | --- |
| **chunk** | 切出来的文本块 | 太大语义混杂，太小检索慢 |
| **overlap** | 相邻块重叠 | 50~100 token，约块大小的 1/10，防一句话被切断 |
| **embedding** | 文本 → 向量 | 检索的基础，常见 1024~1536 维 |
| **向量库** | 存向量并做近邻检索 | Milvus、Elasticsearch、Chroma、Faiss |
| **ANN** | 近似最近邻 | 牺牲一点精度换速度，向量库内部都靠它 |
| **余弦相似度** | 两向量夹角 | 越接近 1 越相似；`点积 / 模长乘积` |
| **BM25** | 关键词检索算法 | TF-IDF + 词频饱和 + 文档长度归一化 |
| **混合检索** | 向量 + 关键词加权 | 常见 0.3 : 0.7；**现在已是标配，不算优化点** |
| **bi-encoder** | 两塔分别编码 | 快，可离线建库，但精度一般 |
| **cross-encoder** | query 和文档拼一起打分 | 准但慢，**只对 top30 左右精排** |
| **rerank** | 重排 | 放在检索之后、组装上下文之前 |
| **HyDE** | 先让模型写假设答案，再用它去检索 | 缓解 query 太短 |
| **语义分块** | 按句向量相似度断点切 | 块变小常常反而掉分，别迷信 |
| **faithfulness / relevance** | 忠实度 / 相关性 | RAG 评估的两个主指标 |

### 9.4 RAG 的四个新进展

| 技术 | 做法 | 效果 |
| --- | --- | --- |
| **Contextual Retrieval** | 给每个 chunk 前面拼一段「这段在全文里讲什么」的上下文，再一起编码 | 检索失败率降 35%；再加 BM25 降 49%；再加重排降 67% |
| **Late Chunking** | 先编码整篇文档，再在 token 向量上切块 | 保留长程上下文，块不再「断章取义」 |
| **GraphRAG** | 抽实体和关系建图，再做社区摘要 | 全局类问题（「这批文档讲了哪几个主题」）明显更强 |
| **Agentic RAG** | 让模型自己决定「搜什么、搜几轮、够不够」 | 多跳问题效果好，代价是延迟和成本 |

<span class="hl-red">一个判断：RAG 的瓶颈从来不在「接哪个向量库」，而在「解析、切块、评估」这三件脏活。</span>

### 9.5 Agent 名词

- **五大组件**：query（理解问题）、plan（拆任务）、action（调工具）、reflection（反思）、memory（记忆）。**灵魂是工作流，核心是组件。**
- **workflow（工作流）**：预先编排好「第几步做什么」。
- **Agent**：工作流 + 一个循环和判断——模型自己决定下一步做什么、用哪个工具。
- **五种工作流模式**：Prompt Chaining（串联）、Routing（路由）、Parallelization（并行）、Orchestrator-Workers（调度者-工作者）、Evaluator-Optimizer（评估者-优化者）。
- **一句话判断该不该上 Agent**：能提示词/RAG 解决就别上，**Agent 是拿延迟和成本换性能**。

### 9.6 推理侧的两个提速技巧

- **投机解码（speculative decoding）**：用一个小的「草稿模型」先猜几个 token，再让大模型**一次并行验证**。猜对的直接收，猜错的回退。**数学上与原模型输出分布完全一致**，不是近似。EAGLE、Medusa、MTP 都是这个思路。
- **约束解码（constrained decoding）**：把「下一个 token 必须符合 JSON 语法」编成一个状态机，采样时把非法 token 直接屏蔽。**结构化输出能做到 100% 合法，靠的就是它。**

## 十、多模态：CNN 到 ViT 到 CLIP 到 LLaVA

| 名词 | 含义 | 在流程里的位置 |
| --- | --- | --- |
| **CNN / 卷积** | 用小窗口逐块扫图，提取局部特征 | 图像编码的传统方案 |
| **池化（pooling）** | 取窗口内最大值 / 平均值 | 降维、提最强特征、增强鲁棒、防过拟合；**不参与训练** |
| **ViT** | 把图切成 patch 当 token，塞进 Transformer | 「不改架构，只改入口」 |
| **patch** | 图像小块，如 16×16×3 | 224×224 切成 14×14 = 196 个 |
| **CLS token** | ViT 额外加的分类占位符 | 输出 `197 × D` 里的第一个 |
| **CLIP** | 图文双塔对比学习 | **把「生成」改成「匹配」**：4 亿对图文，对角拉高、其余压低 |
| **ITC / ITM** | 图文对比 / 图文匹配 | BLIP 的两个预训练任务 |
| **LLaVA** | 视觉编码器 + 投影层 + LLM | 两阶段：先只训投影层，再放开投影层和 LLM |
| **projection（投影层）** | 把 768 维图像特征投到语言模型维度 | 「翻译官」，把图像语言翻成文本语言 |
| **AnyRes** | 高分辨率图切块分别编码再拼回 | LLaVA-1.5 提分辨率的手段 |

### 10.1 一个正在发生的分歧：拼接式 vs 原生多模态

| 路线 | 做法 | 代表 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **拼接式（后接）** | 现成的视觉编码器 + 投影层 + 现成的 LLM | LLaVA、Qwen-VL 早期、多数开源模型 | 便宜、可复用、单卡能训 | 图像和文本在表示上始终「两层皮」 |
| **原生多模态** | 从预训练第一天就把图文混在一起训 | Gemini、GPT-4o | 跨模态推理更强、延迟更低 | 训练成本极高、数据要求极高 |

**判断：开源生态短期仍是拼接式，因为「单卡能训」这件事太重要；但天花板在原生那边。**

## 十一、工程与加速：精度、量化、并行

### 11.1 精度格式

| 格式 | 位数 | 范围 | 精度 | 用在哪 |
| --- | --- | --- | --- | --- |
| FP32 | 1+8+23 | ±3.4×10³⁸ | 高 | 优化器主权重、参数更新 |
| FP16 | 1+5+10 | ±65504 | 中 | 前向反向计算 |
| **BF16** | 1+8+7 | **同 FP32** | 低（尾数 7 位） | **训练默认**：范围够大不溢出 |
| **FP8** | 1+4+3 / 1+5+2 | 较小 | 更低 | **大规模训练新宠**（E4M3 存权重激活，E5M2 存梯度） |
| INT8 | 8 | −128~127 | 低 | 量化推理 |
| INT4 / NF4 | 4 | −8~7 | 很低 | QLoRA、端侧 |
| **MXFP4** | 4（块浮点） | 每 32 个数共享一个指数 | 很低 | 端侧/单卡部署，20B 级模型可进 16GB 显存 |

**为什么训练用 BF16 不用 FP16：** FP16 指数只有 5 位，数值一上亿就 INF；BF16 保留 8 位指数，范围和 FP32 一样，只砍尾数。

**一句话口诀：FP16 是拿来算的，FP32 是拿来更新的。** 优化器的一阶/二阶动量乘上 `1−β` 这种极小系数会数值下溢，必须用 FP32 存。

**FP8 的意义：** 2024 年之后，头部模型开始用 FP8 做大规模训练（DeepSeek-V3 是首个公开验证的案例），显存和带宽直接减半。难点在「哪些张量用 E4M3、哪些用 E5M2、怎么按块缩放」，工程量大但对得起收益。

### 11.2 量化

- **scale**：`(max − min) / (2^b − 1)`。量化 = 减最小值、除 scale、取整；反量化 = 乘 scale、加最小值。
- **误差全在取整**：1.25 → 9 → 反量化回 1.45，差的就是被砍掉的小数。
- **为什么掉点还能用**：softmax 只看相对概率，高概率 token 的排序几乎不变。
- **LLM.int8()**：离群值走 FP16、其余走 INT8，两段分别乘再相加，**数学上等价**，代价是慢约 20%。
- **GPTQ**：离线校准 + 分组量化，推理快。
- **AWQ**：逐层找最优 scale，**不支持微调**。
- **GGUF**：llama.cpp 的单文件格式，支持 LoRA，能跑 CPU。
- **结论：bitsandbytes 别用于线上服务。** 实测在小上下文下比不量化还慢，它是训练期工具（QLoRA 用它），不是推理工具。

### 11.3 蒸馏 / 剪枝

- **黑盒蒸馏 = 一次 SFT**：让教师模型生成 QA 对，训学生模型。R1 蒸馏到 7B/14B/32B 就是这条路。
- **白盒蒸馏**：拿教师的完整概率分布，loss 从 one-hot 交叉熵换成 KL 散度，收敛更快，但拿不到闭源模型的分布。
- **剪枝**：按贡献砍掉 20%~50% 的节点，再微调。**泛化性和专业能力损伤明显，现在很少用。**

### 11.4 FlashAttention / PagedAttention / vLLM / SGLang

- **FlashAttention**：**省的是 IO 不是算力**。朴素注意力要在 SRAM（约 20MB、19TB/s）和 HBM（80GB、1.5TB/s）之间搬六趟，分块后压到两趟，零精度损失换 2~4 倍提速。
- **safe softmax + 在线更新**：分块后 softmax 看不到整行，靠「分子分母同除 e^{max}」加滚动维护 max/分母才成立。这是它真正的巧思。
- **PagedAttention**：把 KV Cache 切成固定大小的 block，用 block table 映射，**最多浪费 3 个 block**（传统预分配浪费 60%~80%）。
- **vLLM**：PagedAttention + 连续批处理 + 共享前缀，显存利用率从 20%~30% 提到 96%，吞吐提升数倍。
- **SGLang**：主打 **RadixAttention**——用前缀树复用多个请求的公共前缀，在「多轮对话、few-shot 相同前缀」场景比 vLLM 更省。

### 11.5 并行

| 名词 | 切什么 | 通信量 | 说明 |
| --- | --- | --- | --- |
| **DP** | 数据 | 随卡数线性增长 | 主卡聚合，别人干等，**瓶颈** |
| **DDP** | 数据 | **约 2P_c，与卡数无关** | Ring-AllReduce：Scatter-Reduce N−1 步 + AllGather N−1 步 |
| **ZeRO-1** | 优化器状态 | 2P_c | 省约 75% 显存 |
| **ZeRO-2** | + 梯度 | 2P_c | 显存降到约 13% |
| **ZeRO-3** | + 参数 | 3P_c（慢 1.5 倍） | 显存降到约 1.5%，前向也要通信 |
| **TP（张量并行）** | 单个矩阵 | 每层算完要合并 | 切注意力与 FFN，开销最低 |
| **PP（流水线并行）** | 按层切 | 只在层边界 | 要靠多批次填充「气泡」 |
| **SP / CP（序列并行）** | 输入序列 | 少 | 解决长上下文激活值爆显存 |
| **EP（专家并行）** | MoE 专家 | 路由通信 | 每个专家是完整前向块，MoE 场景必用 |
| **offload** | 把状态挪到 CPU | 用通信换显存 | 慢但能跑 |

**口诀：显存按 `参数量(B) × 字节数 = GB` 估。** 13B 全量训练状态约 208GB，LoRA 约 42GB，int8 后约 29GB。

## 十二、2024—2026 真正变了什么

这一节只放「旧认知 → 新事实」，方便你判断自己脑子里的知识有没有过期。

| 旧认知 | 新事实 |
| --- | --- |
| 「MoE 是少数派，稠密模型才是主流」 | **2025 年后 MoE 成为旗舰默认**：DeepSeek-V3（671B/37B 激活）、Qwen3-235B-A22B、Llama 4 全是 MoE；稠密模型退到 32B 以下 |
| 「MoE 必须加辅助损失做负载均衡」 | DeepSeek-V3 的 **aux-loss-free** 方案用偏置项调节，不加额外梯度，更稳 |
| 「注意力就是 softmax 全连接」 | **稀疏注意力（DSA）与线性注意力混合架构**开始进主流，长上下文成本大降 |
| 「KV Cache 只能靠 GQA 省」 | **MLA** 把 KV 压到低秩隐空间，压缩率更高；GQA + MLA 并存 |
| 「位置编码要换新的了」 | **RoPE 仍是绝对主流**，变的是 theta、插值和 decoupled 用法 |
| 「对齐就是 RLHF + PPO」 | **RLVR 成为 2025 后训练主线**，可验证任务不用 reward model；GRPO 及其变体取代 PPO 成为常用选择 |
| 「推理就是一次前向」 | **test-time scaling**：让模型多想（更长思维链、多次采样、投票）也能换准确率，o1/R1 把这变成了产品能力 |
| 「量化到 4bit 一定要掉很多点」 | **MXFP4 块浮点**让 20B 级模型进 16GB 显存；FP8 甚至反过来用于训练 |
| 「工具调用每家自己写」 | **MCP** 成为事实标准，一次接入多端复用 |
| 「RAG 就是向量检索 top-k」 | **混合检索 + 重排 + Contextual Retrieval** 是基线；GraphRAG、Agentic RAG 处理多跳与全局问题 |
| 「多模态 = 视觉编码器 + 投影层」 | 开源仍是这条，但**原生多模态**（从预训练就混模态）是天花板方向 |
| 「训练必须 FP16/BF16」 | **FP8 大规模训练**已被验证可行，显存带宽减半 |

## 十三、最容易说错的十句话

| 常见说法 | 对不对 | 正确版本 |
| --- | --- | --- |
| 「现在不用 RoPE 了，都用新的位置编码」 | 错 | RoPE 仍是绝对主流，变的是 theta、插值和 decoupled 用法 |
| 「56 层 train error 更高，是过拟合」 | 错 | 是**网络退化**；过拟合是 train 低 test 高 |
| 「ReLU 已经被淘汰了」 | 半对 | LLM 的 FFN 换成了 SwiGLU；CNN / 端侧仍是 ReLU |
| 「one-hot 没用了」 | 错 | 输入表示被 embedding 取代，但**交叉熵 target、分类监督仍是 one-hot** |
| 「RMSNorm 就是简化版 LayerNorm，效果差一点」 | 错 | 数学上 `RMS² = σ² + μ²` 保证尺度可控，实测不差甚至更好，主流 LLM 全用 |
| 「SFT 能教会模型拒绝」 | 错 | SFT 只教「该怎么答」，拒绝要靠强化学习 |
| 「decoder-only 比 encoder-decoder 先进」 | 半对 | 是**工程和 scaling 上更划算**，翻译 / 语音仍用 encoder-decoder |
| 「量化一定掉点」 | 半对 | LLM.int8() 数学上等价，只是慢 20%；掉点主要来自离群值处理不当 |
| 「MoE 推理更省钱，所以一定更便宜」 | 错 | 省的是**算力**，但显存要装下全部专家；小批量、低并发时反而不划算 |
| 「上下文越长越好」 | 错 | 长上下文有「中间丢失」问题，检索质量、位置分布、KV 显存都是代价 |

---

## 结语

把这些名词串起来看，会发现整条技术线其实只在优化三件事：

1. **同样的参数，装下更多知识**（MoE、更大词表、更好数据）；
2. **同样的算力，算得更快**（GQA、MLA、FlashAttention、量化、稀疏注意力）；
3. **同样的模型，答得更像人想要的**（SFT、RLHF、RLVR、DPO、提示词、RAG、Agent）。

<span class="hl-red">任何一个新名词，只要你能把它归到这三件事里的某一件，并且说清它站在流水线的哪一格，就不会被术语唬住。</span>
