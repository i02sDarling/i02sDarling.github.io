## 一、三种架构，三种接法

提取出**上下文**特征后，三种架构对应不同任务。

![](/images/bian-ma-yi-ci-jie-ma-n-ci/99599a109b.webp)

### Encoder only：只做理解

**encoder only** 先得到输入的上下文表示。

以「我喜欢学习大语言模型」为例，在句前放一个**空字符（代表「这句话之前」）**，让它聚合句中各词的信息，用所得向量代表整句。

该向量可用于分类 **positive 还是 negative**，即正面或负面情感。例如 **淘宝** 评论舆情分析——**BERT** 擅长这类**理解语义**任务。

另一个场景是判断**两句话之间的关系**。后续 RAG 项目会用到句间关系判断：比较「老师今天不在，所以我去打篮球去了」与「老师今天在，所以我去打篮球去了」，考察前后两句的关系。做法是把两句话一起输入，提取关系表示，再用 softmax 等分类输出判断相关性。

两个典型场景：

1. 判断两句话关系的强弱。
2. 判断一句话情感的正负。

### Encoder-Decoder：中间多一根线

**encoder-decoder** 同时使用编码与解码结构，最典型的用途是 **机器翻译**。

例如把「我喜欢大语言模型」翻译成「I love studying AI」。两侧通过一个**交叉处理**的机制联系。

以「好久不见」→ **long time no see** 为例，先输入 **begin**，预测 **long**：既要考虑起始符对它的影响，又要考虑「好久不见」这四个字的影响。对中文编码结果的这次查询，就叫**交叉注意力机制**。

![](/images/bian-ma-yi-ci-jie-ma-n-ci/9ea7cb80f5.webp)

**交叉注意力** 聚合另一序列的信息，**自注意力** 聚合本句信息，比如「好」与「久」之间的关系。

1. 生成 time 时，要考虑 long 和起始符（beginning）对 time 的影响，这属于 **自注意力**。
2. 查询「好久不见」的中文表示，属于 **交叉注意力**。

这个例子里假设 long 的**权重** 0.5，起始符为 0；中文「好」「久」各 0.2，「不」「见」0.1、0。两组数只用来示意关注对象，不合并成一个权重分布。

<span class="hl-red">**交叉注意力只会在编码器和解码器同时出现的结构里出现**</span>。连接编码器和解码器的那根线，就是它。**中文编码结果**作为解码器可查询的上下文。

这一层的概念了解个大概就够了，接下来把运算细节一格一格走一遍。

## 二、Encoder：一次性把中文读懂

![](/images/bian-ma-yi-ci-jie-ma-n-ci/a3af34cfc0.webp)

![](/images/bian-ma-yi-ci-jie-ma-n-ci/1789298641437.png)

Encoder–Decoder 架构图：左侧 Encoder 已产出包含中文**上下文**信息的一串向量，供右侧查询。

一个 Encoder Block 内部长这样：

```markdown
Encoder Block（第 L 层）
输入 x_L（第 1 层 = 中文 embedding + 位置编码；更深层 = 上一层输出）
  │
① Multi-Head Self-Attention（自注意力）
  │    Q = x_L · Wq_e     ← 中文自己的
  │    K = x_L · Wk_e     ← 中文自己的
  │    V = x_L · Wv_e     ← 中文自己的
  │    （无掩码：能看到整句，左右都行）
  │    产出：
  │      · 注意力矩阵（内部加权用，不外传）
  │      · 输出向量 out
  ▼
  z = Add&Norm(x_L + out)
  │
② Feed Forward（FFN）
  ▼
  out' = Add&Norm(z + FFN(z))
  │
  = 本层输出（= 下一层的输入 x_{L+1}）
```

把很多层摞起来看：

```plain
   中文词向量
   │
Block1 → Block2 → … → Block6
   │                       │
   每层输出喂给下一层      最后这个输出
                           │
                      【中文编码结果】
                           │
                    ← 这就是给 Decoder 交叉注意力当 K/V 的东西
```

两个容易被忽略的点：

1. **每个 Block 的 Wq_e / Wk_e / Wv_e 都不一样**——不是同一套参数重复用，是每层各学一套。
2. **Encoder 的注意力矩阵不外传**。真正交给 Decoder 的是最后一个 Block 输出的那串**编码结果**，不是它内部的 Q/K/V。这一点在第六节还会再强调一次。

## 三、Decoder：从 S 开始一个词一个词地蹦

编码完「小狗和小猫玩」后，解码器要生成 **the dogs and cats play**。

解码侧也需要输入表示；先用**随机初始化**做个铺垫，下文再区分训练与推理。它既考虑英文前缀中 dogs 对 and 等关系，也通过**交叉注意力机制**查询中文编码结果。

### 起始符：第一步凭什么开口

![](/images/bian-ma-yi-ci-jie-ma-n-ci/21e0a8d387.webp)

![](/images/bian-ma-yi-ci-jie-ma-n-ci/fea3a6e893.webp)

这里 Outputs 区域也填入了标准翻译答案，需要区分训练和推理。关键区别是 **训练（teacher forcing）** 与 **推理（自回归）** 的输入喂法。

**训练时：整个句子一次性填进去，但位置「错位」了一格**——不是一步一步喂，而是把整句一次填进注意力矩阵：

```plain
Decoder 输入（shifted right）:  [S]  The  dogs  and  cats  play
要预测的目标（labels）:          The  dogs  and  cats  play  [E]
                   位置:         0    1    2    3    4     5
```

+ 位置 0 是 `[S]`，它负责预测位置 1 的 `The`
+ 位置 1 是 `The`，它负责预测位置 2 的 `dogs`
+ …以此类推，<span class="hl-red">**每个位置的输出，预测它右边紧挨着的下一个 token**</span>

所以训练时一次喂 6 个 token，同时算 6 个位置的预测，**并行**。这就是 teacher forcing 的高效之处——不用真的一个字一个字蹦。

**但注意力矩阵里有个“因果掩码”（causal mask）**：位置 t 做注意力时，**只能看 0~t 自己及左边的词**，不能看右边的。位置 2（`dogs`）可关注 `[S] The dogs`，不能偷看右侧 `and cats play`。

**`[S]` 是必须的吗？必须。**它叫**起始符（BOS / Start Token）**，作用就是「启动生成」：

+ 推理时第一步，Decoder 手里**一个词都还没有**，那它靠什么开口？靠 `[S]`。
+ 所以训练时必须把 `[S]` 也喂进去，让模型学会“见到起始符，第一步该吐出哪个词（The）”。
+ 没有它，模型推理时就没有“起点”，第一步不知道从哪开始。

（有些模型把 `[EOS]` 兼当起始符，但“需要一个标记来启动”这个本质不变。）

### 把「降维 + 预测」串起来看

这就是**每个 token 的标准处理链**：

```plain
token 索引（如 vocab 15 里的 one）───┐
   │ 乘嵌入矩阵 W_e（15→5 降维）      │  ← 把词变成 5 维向量
   ▼                                 │
[S] 的 5 维向量 ──→ 送入模型 ──→ 输出 5 维向量
   （在模型内部做自注意力/交叉注意力+前馈）
   │ 乘输出矩阵 W_o（5→15 升维）      │  ← 映射回词表
   ▼                                 │
15 个词各自一个分数 ──softmax──> 概率分布
                                     │
                    argmax / 和真值比 → 预测/损失
```

+ **降维矩阵（15→5）** = 词嵌入，把“词的编号”变成“带语义的向量”
+ **升维+softmax（5→15）** = 输出投影，把模型算出的语义变成“下一个词是谁”的概率
+ 训练时：位置 0（`[S]`）算出来的分布，跟真值 `The` 比，算损失
+ 推理时：位置 0（`[S]`）算出来的分布，取概率最高的 = `The`，然后把 `The` 追加进输入，再算下一步

**一句话把“训练喂整句”和“推理逐词蹦”对齐**

|  | 输入 | 做法 |
| --- | --- | --- |
| 训练 | `[S] The dogs and cats play` | **整句并行**喂进去，错位预测下一个词，因果掩码防偷看 |
| 推理 | 一开始只有 `[S]` | **逐步**：`[S]→The→dogs→and→cats→play`，每步把刚生成的追加进去再算下一个 |

「从 S 逐步生成 the dogs and cats play」是 **推理**；「一次输入移位后的目标句」是 **训练**。模型架构与参数来源相同，输入方式不同。

### 第一步具体怎么走

推理开始时只有起始符 S，之后逐步生成「the dogs and cats play」。

将 S 的词表表示经 15→5 的嵌入矩阵变成 5 维向量，输入 Decoder，再预测下一个 token **the** 的概率；嵌入与投影操作可与 Encoder 对照。

![](/images/bian-ma-yi-ci-jie-ma-n-ci/7fd3e92f50.webp)

## 四、先后顺序：编码一次，解码 N 次

**Encoder 先发生，一次性做完，然后把结果「冻结」在那里；Decoder 再在它之后一个词一个词地解码。** 以推理翻译为例，时间线是这样：

```plain
第 0 步：Encoder 读入 "小猫和小狗玩"
         → 一次性（并行）算完整个句子的自注意力 + FFN
         → 产出"中文语义编码"（一串向量）★ 之后不再变化

第 1 步：Decoder 拿着 [S] + 中文编码 → 预测 "The"
第 2 步：Decoder 拿着 [S] The + 中文编码 → 预测 "dogs"
第 3 步：Decoder 拿着 [S] The dogs + 中文编码 → 预测 "and"
...
最后一步：Decoder 预测出 [E]（结束符），停止
```

**关键点**

|  | 何时发生 | 怎么算 | 用几次 |
| --- | --- | --- | --- |
| **Encoder** | **最先**，一次性 | 对中文整句并行自注意力 | 只算一次，结果常驻 |
| **Decoder** | Encoder 之后 | 逐词自回归 | 每生成一个词就用一次 |

**Encoder 的输出是“定值”**：从第一个英文词 `The` 到最后一个词，Decode 每一步的 cross-attention 都在**反复查阅同一个编码结果**，但编码本身不再重算。

**一句话类比**

+ **Encoder = 先读题、把题目理解透**（一次完成，写出“解题笔记”）
+ **Decoder = 开始答题**，每写一个英文词，就**回头翻一眼笔记**（cross-attention），并结合已经写出的词（self-attention）决定下一个词

> <span class="hl-red-bg">**编码先、解码后；编码一次，解码 N 次（N = 生成词的个数）。**</span> 训练时（teacher forcing）也是这个顺序：先让 Encoder 出结果，Decoder 再基于它 + 目标句子并行前向传播。
>

### 顺便拆两个容易混的概念

**解码步是时间，Block 是空间。**

| 概念 | 是什么 | 干什么 | 数量/维度 |
| --- | --- | --- | --- |
| **解码步** | 生成**一个词**的一次前向传播 | 把当前前缀跑一遍整个 Decoder，预测下一个词 | **时间轴**：5 个词 = 5 步 |
| **Block / 层** | 一个处理单元：自注意力→Add&Norm→交叉注意力→Add&Norm→FFN→Add&Norm | 对表示做**一轮加工**（不产词） | **空间轴**：堆叠 N× 个（如 6 个） |
| **FFN** | Block 内部的前馈网络 | 逐词**独立非线性加工** | 每个 Block 各有自己的一套参数 |

```plain
第 1 步 [S]          → Block1→Block2→…→Block6 → 预测 The
第 2 步 [S] The      → Block1→Block2→…→Block6 → 预测 dogs
第 3 步 [S] The dogs → … → 预测 and
…
第 5 步 …            → … → 预测 play
```

+ **横向（步）**：5 次前向传播
+ **纵向（层/Block）**：每次前向都过 6 个 Block，每个 Block 用自己的参数
+ 所以：**生成一个词要跑完 N 个 Block；而同一套 Block 会在每一步被反复用**

## 五、三套 Wq/Wk/Wv，和那些“同一个”的问法

这是全篇最容易吵起来的地方，一次说清。

**一个 Transformer 里有三套独立的 Wq/Wk/Wv**：

| 子层 | Q 来自 | K 来自 | V 来自 | 它的 Wq/Wk/Wv |
| --- | --- | --- | --- | --- |
| **Encoder 自注意力** | 中文 `小猫和小狗玩` | 同一个句子 | 同一个句子 | 第一套（encoder 自己的） |
| **Decoder 掩码自注意力** | 英文 `the dogs and cats` | 同一个英文句 | 同一个英文句 | 第二套 |
| **Decoder 交叉注意力** | 英文（decoder 输出） | **中文编码结果** | **中文编码结果** | **第三套（独立）** |

**为什么不能共用？** 因为每套矩阵的“任务”不同：

+ encoder 的 W 学会：中文内部词与词的关联
+ decoder 掩码自注意力的 W 学会：英文自己前后的语法、搭配
+ cross-attention 的 W 学会：**英文 ↔ 中文 之间的对应关系**

### 那到底什么“是同一个”

同一个子层里，Wq 对**所有词、所有解码步、训练和推理**都是同一个：

+ 对一个句子里**每个词**：`Q_i = x_i · Wq`，所有词共用同一个 Wq
+ 对**每一步解码**（`[S]→The→dogs→...`）：每步都是拿当前序列所有词的向量 × **同一个 Wq**
+ 这就是“**参数共享 / 权重绑定**”：一套 Wq 用在整个序列的所有位置、所有时间步

但**不同层之间不一样**：

| 维度 | 变不变 | 为什么 |
| --- | --- | --- |
| 同一层内，不同解码步（Block3 在第 1 步 vs 第 5 步） | **不变**（复用） | 参数是固定的，每步只是“再次执行”同一个矩阵 |
| 不同层 / 不同 Block（Block1 vs Block2） | **不同**（每层各一套） | 每层独立学习，各学各的投影 |
| 不同子层（自注意力 Wk vs 交叉注意力 Wk_cross） | **不同** | 本来就是两套矩阵 |
| 训练 vs 推理 | 训练时更新、推理时冻结 | 参数只在反向传播中更新 |

一句话：**按层分（每层一套、互不相同），按步共享（同层每步复用同一个）。**

### 训练与推理的分界

+ **训练**：Wq 是参数，跟着反向传播不断更新（学习出来的）
+ **推理**：用的是训练完**冻结**的那个 Wq，不再更新

训练时它在变（学习），推理时它不变（用）。推理阶段 Wq 的值就是训练收敛后的最终值。

<span class="hl-red">**顺带纠正一个常见误读**</span>：推理时把模型自己生成的字再喂回去，并不会让它“学坏”——因为推理不更新参数。生成质量下降是误差累积的问题，不是权重被改坏了。

## 六、交叉注意力：Q 还是自己的

![](/images/bian-ma-yi-ci-jie-ma-n-ci/624b64d701.webp)

图示已进入第二阶段——**交叉注意力**；完整起点如下：S → **掩码自注意力** → 交叉注意力 → FFN → 输出投影，预测「The」。

即使只有 `[S]`，自注意力也会产生中间**注意力矩阵**。它是**算出来的中间量**，直接参与下一个词的预测：加权 V，再经过后续层。

**一次解码步 = 整个 Decoder（所有 N 个 block）完整跑一遍**

```markdown
输入 x（英文）
① Masked Self-Attention：
     Q₁ = x · Wq_自          ← 第 1 个 Q（英文自己）
     K₁ = x · Wk_自
     V₁ = x · Wv_自
     Q₁·K₁ᵀ → 自注意力矩阵（带因果掩码）
     → 加权 V₁ → z = Add&Norm(x + out₁)

② Cross-Attention：
     Q₂ = z · Wq_cross       ← 第 2 个 Q（z = 自注意力输出后的英文）
     K₂ = 中文编码结果 · Wk_cross
     V₂ = 中文编码结果 · Wv_cross
     Q₂·K₂ᵀ → 交叉注意力矩阵
     → 加权 V₂ → z' = Add&Norm(z + out₂)

正确：K₂ = 中文编码结果 × Wk_cross
（是编码结果投影来的，跟 Q 无关）
然后才：Q₂·K₂ᵀ 做匹配 → 得到"注意力分数矩阵"

中文编码结果是什么
中文 → Encoder（自注意力×N层 + FFN）→ 【中文编码结果】→ 给交叉注意力当 K/V 的原料

Encoder 的 Q/K/V 只在 Encoder 自己内部用，不传给交叉注意力

一次解码步的真实流程
输入：[S]（或 [S] The dogs and cats）
       │
Block1 ─┘  （只做加工：自注意力+交叉注意力+FFN，更新表示）
Block2 ─┘  （继续加工）
Block3 ─┘
...
Block6 ─┘  （最后一个 block 的输出）
       │
  ×Wo + softmax
       │
 预测出 1 个词（比如 play）
```

查询仍然来自解码侧：<span class="hl-red-bg">**Q 还是自己的**——Q 还是乘以 Wq_cross，得到自己的 Q。</span>

> 这里的 embedding × Wq 是第一次。
>

**交叉注意力**的 K/V 则需要来自中文上下文。来源是整个 Encoder 完成后得到的一串「**中文编码结果**」，不是 Encoder 内部的 Q/K/V。K 由**中文编码结果**乘 Wk_cross 得到；它不由 Q 投影而来。

一句话概括：**就是用解码阶段的 Q 去乘以编码阶段的 K**。

```markdown
输入 x（第 1 层 = embedding + 位置编码）
  │
① Masked Self-Attention
  │    Q₁=x·Wq_自, K₁=x·Wk_自, V₁=x·Wv_自   ← 这一步的 Q/K/V 才是用 embedding 算的
  │    产出两个东西：
  │      · 注意力矩阵（权重，仅供内部加权 V 用）
  │      · 输出向量 out₁
  ▼
  z = Add&Norm(x + out₁)     ← z 是"自注意力的输出向量"（加工+残差+归一化后的）
  │
② Cross-Attention
  │    Q = z · Wq_cross      ← 用的是 z！不是 embedding！
  │    K = 中文编码结果 · Wk_cross
  │    V = 中文编码结果 · Wv_cross
  ▼
  …→ FFN → 输出
```

得到**交叉注意力**权重后，再乘 V，形成交叉注意力输出。

![](/images/bian-ma-yi-ci-jie-ma-n-ci/be5ee1c61f.webp)

把两个子层串起来看：先处理英文内部关系，再查询中文。

**交叉注意力的运算**

```plain
① 分数矩阵 = Q · Kᵀ / √d_k
        ↓
② 注意力权重 = softmax(分数矩阵)
        ↓
③ 注意力输出 = 权重 × V          （加权求和）
        ↓
④ 多头结果拼接 → × Wo            （输出投影）
        ↓
⑤ Add：注意力输出 + 原输入        （残差连接）
        ↓
⑥ Norm：LayerNorm                （层归一化）
        ↓
   Add&Norm 的结果 → 交给下一层
```

第一个子层的作用是：掩码自注意力先建模 dogs、and、cats 等英文前缀内部的相互影响。接着由自注意力后的英文隐藏表示重新投影出**交叉注意力** Q，去查询中文 K。

「Q 还是自己的」指的是**来源在解码侧**，不是“沿用同一个数值”——自注意力的那个 Q 和交叉注意力的这个 Q 是两个不同的向量。

> 用 Q 去查对应的那个锁孔 K，再乘以 V，看最终偏移多少。
>

![](/images/bian-ma-yi-ci-jie-ma-n-ci/1789495160982.png)

Q 到中文**编码器**已经做好的语义空间里查，按权重聚合 V；经过输出投影、残差与 LayerNorm，形成后续表示。

![](/images/bian-ma-yi-ci-jie-ma-n-ci/1789495871816.png)

输出示例：**前缀**为 the、dogs、and、cats，下一 token 的候选中 S=0.012，and=9×10⁻⁶，play=0.622；按图中最大概率选择 play，得到「the dogs and cats play」。

![](/images/bian-ma-yi-ci-jie-ma-n-ci/1789495956770.png)

> K 和 Q 相乘得到的矩阵，<span class="hl-red">**注意力的维度是按 sequence 维度来的**</span>，因为要看四个单词之间互相的影响。
>

四个英文词做自注意力，分数矩阵为 4×4；**交叉注意力**则为「解码长度 × 编码长度」，不一定正方形。

## 七、自注意力 vs 交叉注意力：只差输入来源

**步骤完全一样，一个都不差；区别只在于 Q/K/V 从哪来。** 两条流水线走的是同一套“机器”，只是喂给它的东西不同。

| 步骤 | 自注意力 | 交叉注意力 |
| --- | --- | --- |
| ① 分数 | Q·Kᵀ/√d_k | Q·Kᵀ/√d_k |
| ② softmax | 有 | 有 |
| ③ 权重×V | 有 | 有 |
| ④ ×Wo（输出投影） | 有 | 有 |
| ⑤ 残差 Add | 有 | 有 |
| ⑥ LayerNorm | 有 | 有 |

**公式、流程、Add&Norm 全一样。** 代码里根本是同一个函数，只是传参不同。

**真正的区别：Q/K/V 的来源**

|  | Q 来自 | K 来自 | V 来自 | 掩码 |
| --- | --- | --- | --- | --- |
| **自注意力** | **同一个句子**（本句自己） | 同一个句子 | 同一个句子 | Encoder 无 / Decoder 有 causal mask |
| **交叉注意力** | **解码器英文** | **编码器中文** | **编码器中文** | 无 |

+ 自注意力 = **“自己内部互看”**：比如英文句子里 `dogs` 看 `cats`
+ 交叉注意力 = **“英文去看中文”**：`dogs` 去查 `小猫和小狗玩`

**另外两个小差异**

1. **注意力矩阵形状**：自注意力是 `句子长度 × 句子长度`（正方形，如 4×4）；交叉注意力是 `解码长度 × 编码长度`（长方形，如 4×6）。
2. **解码器的自注意力带掩码**：只能看“已生成的左边”，不能看右边未来；交叉注意力不需要——中文早就全部生成好了。

> 自注意力和交叉注意力的<span class="hl-red">**运算步骤一模一样**</span>（分数→softmax→×V→×Wo→Add&Norm），区别只有三点：**Q/K/V 来源**、**矩阵形状**、以及**解码器自注意力多了个掩码**。
>

## 八、反向验证：GPT 为什么没有交叉注意力

**问：GPT 只有解码器，交叉注意力是如何实现的？**

**答：严格来说，GPT 没有所谓的交叉注意力机制。**

例如用「我喜欢学习大语言」预测「模型」，只需关注当前前缀，不需要另一个编码器序列。Encoder–Decoder 翻译要同时处理中文与英文前缀；而 Decoder-only **只存在自注意力**，没有那一层跨序列查询。

那 GPT 怎么做翻译？把原文和指令一起当**续写前缀**：

```plain
I like LLM. Translate it in Chinese.
```

模型接着这个前缀往下写，输出的就是中文。它并没有“左侧文字先 encode、再去和中文做交叉注意力”这一步，**它不需要**。

这其实是这一篇最好的反证：**交叉注意力不是注意力的必需品，它是“两个序列要对接”才长出来的零件。** 只要任务能塞进一个序列里续写，就不需要它。

---

三篇到这里收束。

回到最开始那个问题——Transformer 到底在算什么？现在可以一句话答完：

**把一句话切成 token、查成向量、加上位置，然后每个词带着自己的提问（Q）去和所有词的标签（K）对分，按分数把内容（V）搬回来一点，加回自己身上；这件事重复几十层，每层都比上一层更懂这句话；如果要翻译，就再让一层“英文看中文”的注意力去查另一边。最后乘一个矩阵、过 softmax，选出下一个词。**

三篇各自的分工也清楚了：

| 篇 | 回答的问题 | 关键结论 |
| --- | --- | --- |
| 一 | 它在算什么、一句话怎么进来 | Y = F(X)；token → 向量 → n×d 矩阵 → 加位置编码 |
| 二 | 一个 Block 内部算了什么 | 注意力只做一件事：按 Q·K 的权重搬 V，再加回自己 |
| 三 | 多个 Block 怎么拼、两边怎么对接 | 编码一次解码 N 次；交叉注意力的 Q 来自解码侧 |

真正要动手写代码时，还有三件事值得单独翻：形状怎么对、Excel 里一格一格算是什么样、手撕 Attention 的完整实现。那些不在这三篇的范围里——但只要你记住上面那条主线，细节都能挂上去。
